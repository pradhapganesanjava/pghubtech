Approach — roll your own ordered index

TreeMap is banned, so implement the ordered structure. Three viable choices, trading insert cost against simplicity:

Structureadd / removesearch(t)search(t1,t2)
Balanced BST / Skip listO(log n)O(log n)O(log n + k)
Sorted array + binary searchO(n) (shift)O(log n)O(log n + k)
Plain BSTO(h)O(h)O(h + k)

BST + bounded in-order range query (the #938 trick)

def search(root, t):                    # point lookup
    while root:
        if t == root.key: return root.val
        root = root.left if t < root.key else root.right
    return None

def range_query(root, lo, hi, out):     # all keys in [lo, hi]
    if not root: return
    if root.key > lo:                    # only go left if keys < root could be >= lo
        range_query(root.left, lo, hi, out)
    if lo <= root.key <= hi:
        out.append((root.key, root.val))
    if root.key < hi:                    # only go right if keys > root could be <= hi
        range_query(root.right, lo, hi, out)

add = BST insert; remove = BST delete (two-child case: replace with in-order successor). Balance (AVL/red-black) or a skip list keeps everything O(log n). The pruning conditions are what keep the range walk at O(log n + k) instead of O(n).

Follow-up trio

  • Multi-threaded — reads (search / range) vs writes (add / remove): a ReadWriteLock on the tree (many readers, one writer), or a lock-free skip list (CAS on forward pointers) for high concurrency.
  • Streaming — if timestamps arrive strictly increasing, appends keep a sorted array ordered in O(1) — no tree needed; range = two binary searches.
  • O(1)-space — structure is inherently O(n); range query uses O(h) recursion (iterate with an explicit stack for O(1) beyond output).
