Approach

1) Prefix filter (set of deleted paths)

A path survives iff it is neither a deleted path nor a descendant of one. Put the delete list in a set; for each path, check itself and every ancestor prefix against the set.

deleted = set(to_delete)
def keep(p):
    parts = p.split('/')
    for k in range(1, len(parts) + 1):        # every ancestor prefix incl. p
        if '/'.join(parts[:k]) in deleted:    # p == d  OR  p sits under d/...
            return False
    return True
return [p for p in paths if keep(p)]

O(total path segments). A cheaper membership test: descendant iff p == d or p.startswith(d + \"/\") for some deleted d — the trailing / avoids matching \"California/San Franciscoland\".

2) Trie prune (the trie-basic route)

Insert every path as a chain of level-nodes into a trie. For each delete, navigate to that node and detach it from its parent — the whole subtree (all descendants) disappears in one cut. Then collect the surviving root-to-node paths. Better when deletes are many or you query repeatedly.

Edge cases

  • Prefix collision: \"California/San Franciscoland\" must NOT be removed by deleting \"California/San Francisco\" — compare on full segments (or startswith(d + \"/\")), not raw string prefix.
  • Delete order / overlap: deleting an ancestor subsumes its descendants; redundant deletes are harmless with the set approach.
  • A deleted path not present in the input is a no-op.

Follow-up trio

  • Multi-threaded — the per-path keep() checks are independent (shared read-only deleted-set), so partition the path list across threads.
  • Streaming — paths/deletes arrive online: maintain the trie; an add inserts a chain, a delete detaches a subtree — both O(depth), no full rescan.
  • O(1)-space — the set-filter uses O(#deletes) beyond the output; the trie is O(total segments) but enables O(depth) deletes.
