Design — a dependency DAG behind a small API

State: an adjacency map (dep → tasks that depend on it) plus an indegree count per task. Three classic graph routines compose the whole system.

class Workflow:
    def __init__(self):
        self.adj = {}          # node -> set of successors (dependents)
        self.indeg = {}        # node -> in-degree

    def add_task(self, t):
        self.adj.setdefault(t, set()); self.indeg.setdefault(t, 0)

    def add_dependency(self, t, dep):       # t depends on dep  => edge dep -> t
        if t not in self.adj[dep]:
            self.adj[dep].add(t); self.indeg[t] += 1

    def order(self):                         # Kahn topological sort
        indeg = dict(self.indeg)
        q = deque(t for t in self.adj if indeg[t] == 0)
        out = []
        while q:
            u = q.popleft(); out.append(u)
            for v in self.adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0: q.append(v)
        return out if len(out) == len(self.adj) else None   # None => CYCLE

    def clone(self):                         # deep copy (Clone Graph #133 style)
        w = Workflow()
        for t in self.adj: w.add_task(t)
        for u in self.adj:
            for v in self.adj[u]:
                w.adj[u].add(v); w.indeg[v] += 1
        return w                              # no references shared with self
  • order() — Kahn's BFS; if fewer than N tasks are emitted, a cycle exists (no valid order).
  • clone() — recreate every node, then re-link edges via an old→new mapping, so the copy shares no objects with the original (key point of #133 / #138).

Per-task execution order (DFS post-order)

When the ask is "print the order for a specific task" (e.g. Task A → C B A), don't run a global Kahn sort — do a post-order DFS from that task: recurse into each dependency first, then append the task itself. The result is a topological order rooted at the task, and a 3-color marking detects cycles in the same pass.

WHITE, GRAY, BLACK = 0, 1, 2          # unseen / in-progress / done

def exec_order(task, deps):            # deps[t] = tasks that t depends on
    color = defaultdict(int); out = []
    def dfs(t):
        color[t] = GRAY
        for dep in deps[t]:
            if color[dep] == GRAY: raise CycleError   # back-edge => cycle
            if color[dep] == WHITE: dfs(dep)
        color[t] = BLACK
        out.append(t)                  # task printed AFTER its dependencies
    dfs(task)
    return out                          # exec_order(A) -> [C, B, A]

The GRAY (in-progress) mark is the key: hitting a GRAY node means a back-edge, i.e. a cycle. This is the recursive single-root counterpart to the global Kahn order above — same topological guarantee, and it doubles as Part 4's cycle check.

Follow-up trio

  • Multi-threaded — run order() wave-by-wave (each Kahn layer is an independent batch executable in parallel); guard the shared indegree counters with atomics. Clone's per-node copies are independent.
  • Streaming — tasks/deps arrive online: keep indegrees current on each add_dependency; maintain a live set of indegree-0 tasks so order() / "next runnable" is incremental, not a full rebuild.
  • O(1)-space — cycle detection alone needs only the indegree counters + queue (O(V)); DFS 3-color is the recursive alternative. The graph itself is inherently O(V+E).
