Approach — scan 4 axes from the last move

Only the just-placed piece can complete a line, so there's no need to rescan the whole board. From (r, c) for player P, check each of the four axes; for each, count consecutive P cells in both directions and add 1 for the move itself.

def result(board, r, c, P):
    m, n = len(board), len(board[0])
    def walk(dr, dc):
        cnt, i, j = 0, r + dr, c + dc
        while 0 <= i < m and 0 <= j < n and board[i][j] == P:
            cnt += 1; i += dr; j += dc
        return cnt
    for dr, dc in ((0,1), (1,0), (1,1), (1,-1)):   # H, V, diag, anti-diag
        if 1 + walk(dr, dc) + walk(-dr, -dc) >= 4:
            return f"{P} wins"
    return "draw" if all(board[i][j] != '.' for i in range(m) for j in range(n)) else "ongoing"

O(1) per move for a fixed target length (4 axes × 2 directions × ≤3 steps); O(k) for a general k-in-a-row. Each axis pairs a direction with its opposite so a piece in the middle of a run is still detected.

If gravity applies (real Connect Four)

A move drops to the lowest empty cell of a column: r = the lowest empty row in column c. The win check is identical once you know the landing cell.

Follow-up trio

  • Multi-threaded — the 4 axis checks are independent and can run in parallel (trivial fan-out), short-circuiting on the first win. For many concurrent games, shard by board id.
  • Streaming — moves arrive as a sequence: keep the board and run the O(1) last-move check per move — never a full-board rescan. (Optionally cache per-cell run-lengths in each direction to update incrementally.)
  • O(1)-space — the scan uses O(1) beyond the board; the draw check is O(mn) but can be replaced by a running filled-count incremented per move.
