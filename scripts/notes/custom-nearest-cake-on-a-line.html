Approach

Single query — scan both directions

From person p, walk left for the nearest 1 and right for the nearest 1; return whichever index is closer (the guarantee of no ties makes the winner unique). O(n) worst case, O(1) space.

def nearest_cake(A, p):
    n = len(A); L = R = -1
    for i in range(p, -1, -1):      # nearest cake to the left (incl. none)
        if A[i] == '1': L = i; break
    for j in range(p, n):           # nearest cake to the right
        if A[j] == '1': R = j; break
    if L == -1 and R == -1: return -1
    if L == -1: return R
    if R == -1: return L
    return L if (p - L) <= (R - p) else R

All persons at once — two-pass (like LC 821)

If you must answer for every index, precompute nearestLeft[i] (last cake index at or before i) in a forward pass and nearestRight[i] (next cake index at or after i) in a backward pass; each index picks the closer. O(n) total.

Follow-up trio

  • Multi-threaded — the left-pass and right-pass are independent: run them concurrently and merge. For many person queries, shard the query list across threads (shared read-only nearestLeft/nearestRight arrays).
  • Streaming — cells arrive online: track the index of the last-seen cake; a person's left-answer is known immediately, and a pending person resolves the moment the next cake appears (compare to its remembered left cake).
  • O(1)-space — the single-query scan already uses O(1) extra. The all-persons two-pass needs O(n) output arrays.
