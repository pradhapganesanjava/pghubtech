Document Store with Boolean Predicate Search

A progressive (3-part) build: an in-memory document store, full boolean predicate evaluation, then a multi-document query backed by an inverted index — plus a distributed-system follow-up.

Part 1 — INSERT_DOC and OR-only CHECK_CONTAINS

Problem

Maintain an in-memory map from filename to the set of words it contains.

  • INSERT_DOC <filename> <word1> <word2> ... — store the words under filename. Return ERROR if the document already exists or no words were given, else OK.
  • CHECK_CONTAINS <filename> <predicate> — here the predicate is an OR-chain (a, a || b, a || b || c). Print true if at least one term is in the file's word set, else false; ERROR if the filename is unknown.

Example

INSERT_DOC notes.txt apple banana cherry
INSERT_DOC notes.txt fig
INSERT_DOC empty.txt
CHECK_CONTAINS notes.txt apple
CHECK_CONTAINS notes.txt grape
CHECK_CONTAINS notes.txt grape || cherry
CHECK_CONTAINS missing.txt apple
---- expected ----
OK
ERROR
ERROR
true
false
true
ERROR

Solution

The Server owns one documents dict keyed by filename. The dispatcher reads a line, routes by command name, and prints exactly one line per command.

import sys

class Server:
    def __init__(self) -> None:
        self.documents: dict[str, set[str]] = {}

    def insert_doc(self, filename: str, words: list[str]) -> str:
        if not words:
            return "ERROR"
        if filename in self.documents:
            return "ERROR"
        self.documents[filename] = set(words)
        return "OK"

    def check_contains(self, filename: str, predicate: str) -> str:
        if filename not in self.documents:
            return "ERROR"
        words = self.documents[filename]
        terms = [t.strip() for t in predicate.split("||")]
        return "true" if any(t in words for t in terms) else "false"

def main() -> None:
    server = Server()
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        try:
            if line.startswith("INSERT_DOC "):
                parts = line.split()
                filename, words = parts[1], parts[2:]
                print(server.insert_doc(filename, words))
            elif line.startswith("CHECK_CONTAINS "):
                _, filename, predicate = line.split(maxsplit=2)
                print(server.check_contains(filename, predicate))
            else:
                print("ERROR")
        except (ValueError, IndexError):
            print("ERROR")

Design choices that carry forward:

  • Documents are set[str] → O(1) term lookup, automatic dedupe. Word frequency isn't needed for boolean queries.
  • split(maxsplit=2) keeps the predicate's internal whitespace intact; Part 2 reuses this exact dispatch.
  • Predicate parsing is isolated — Part 2 lifts it into a free function so Part 3 can call it per document.

Complexity: INSERT_DOC O(W) for W words; CHECK_CONTAINS O(T) for T terms.

Part 2 — Full Boolean Predicates

Problem

Extend the predicate to mix && and ||, with && binding tighter than ||: a && b || c ≡ (a && b) || c. Part 1 validation still applies.

Example

INSERT_DOC f1 apple banana cherry
CHECK_CONTAINS f1 apple && banana
CHECK_CONTAINS f1 apple && grape
CHECK_CONTAINS f1 apple && grape || cherry
CHECK_CONTAINS f1 grape && pear || apple && date
---- expected ----
OK
true
false
true
false

Solution

Pull the evaluator out of the class. The key insight: a && b || c && d is already in disjunctive normal form. Split on || to get OR-clauses, split each on && to get AND-terms; the predicate is true iff any clause has all its terms present.

def evaluate_predicate(words: set[str], predicate: str) -> bool:
    for clause in predicate.split("||"):
        terms = [t.strip() for t in clause.split("&&")]
        if not all(terms):
            continue
        if all(t in words for t in terms):
            return True
    return False

check_contains becomes a one-liner:

def check_contains(self, filename: str, predicate: str) -> str:
    if filename not in self.documents:
        return "ERROR"
    return "true" if evaluate_predicate(self.documents[filename], predicate) else "false"

Why DNF splitting works: with && higher-precedence than || and no parentheses, every predicate is structurally (term && ...) || (term && ...) || .... Split on the lower-precedence operator first, then the higher — no recursion needed.

Stretch: if the interviewer adds parentheses or a ! operator, linear splitting breaks. The fix is a recursive-descent parser with three levels: or_expr -> and_expr ('||' and_expr)*, and_expr -> unary ('&&' unary)*, unary -> '!'? term | '(' or_expr ')'.

Complexity: O(T), T = total terms.

Part 3 — GET_ALL_FILES with an Inverted Index

Problem

GET_ALL_FILES <predicate> — return every stored document satisfying the predicate (same grammar as Part 2). Print matching filenames in lexicographic order, comma-joined, no spaces; print None if nothing matches.

Example

INSERT_DOC f1 apple banana
INSERT_DOC f2 banana cherry
INSERT_DOC f3 cherry date
GET_ALL_FILES apple
GET_ALL_FILES banana
GET_ALL_FILES apple || cherry
GET_ALL_FILES banana && cherry
GET_ALL_FILES grape
---- expected ----
OK
OK
OK
f1
f1,f2
f1,f2,f3
f2
None

Naive solution

Reuse evaluate_predicate against every document — correct but O(F × T) per query.

def get_all_files(self, predicate: str) -> str:
    matches = sorted(
        name for name, words in self.documents.items()
        if evaluate_predicate(words, predicate)
    )
    return ",".join(matches) if matches else "None"

Optimized — inverted index

Keep a second map index: dict[str, set[str]] from word → set of filenames. Shift cost from query time to insert time. Per AND-clause, intersect the posting lists; union the per-clause results for the OR.

class Server:
    def __init__(self) -> None:
        self.documents: dict[str, set[str]] = {}
        self.index: dict[str, set[str]] = {}

    def insert_doc(self, filename: str, words: list[str]) -> str:
        if not words or filename in self.documents:
            return "ERROR"
        unique = set(words)
        self.documents[filename] = unique
        for w in unique:
            self.index.setdefault(w, set()).add(filename)
        return "OK"

    def get_all_files(self, predicate: str) -> str:
        matches: set[str] = set()
        for clause in predicate.split("||"):
            terms = [t.strip() for t in clause.split("&&")]
            if not all(terms):
                continue
            postings = [self.index.get(t, set()) for t in terms]
            clause_match = set.intersection(*postings) if postings else set()
            matches |= clause_match
        if not matches:
            return "None"
        return ",".join(sorted(matches))

check_contains is unchanged — only insert_doc and get_all_files touch the index. Dispatcher additions:

elif line.startswith("CHECK_CONTAINS "):
    _, filename, predicate = line.split(maxsplit=2)
    print(server.check_contains(filename, predicate))
elif line.startswith("GET_ALL_FILES "):
    _, predicate = line.split(maxsplit=1)
    print(server.get_all_files(predicate))

Why faster: the query only touches posting lists of words in the predicate, not every document. Intersect in increasing posting-list size to keep the running set small (sort postings by len() before set.intersection — the standard production tweak).

Complexity: INSERT_DOC O(W); GET_ALL_FILES O(Σ posting-list sizes for the predicate's terms) — typically « F.

Follow-up — Distributed System Design

Sharding

  • Shard by document id (filename). Hash the filename; route INSERT_DOC and per-file CHECK_CONTAINS to one shard — cheap writes + per-file reads. Cost lands on GET_ALL_FILES, which must fan out to every shard and merge at the coordinator.
  • Shard by term (inverted-index partitioning). Hash each word; store its posting list on one shard. GET_ALL_FILES touches only a few shards, but a W-word INSERT_DOC triggers W cross-shard writes.

Most production search systems use document sharding (writes » GET_ALL_FILES, throughput scales with shard count). Use consistent hashing on the filename so adding/removing shards re-routes only a slice of the keyspace.

Replication

Per shard, run a leader + two followers (RF=3). Writes hit the leader, replicate sync/async per durability needs. CHECK_CONTAINS / GET_ALL_FILES reads can hit any follower — more read throughput, at the cost of read-your-writes lag on async replicas.

Consistency

For read-your-writes, route follow-up reads to the leader or attach a write-version token followers check before serving. For most search workloads eventual consistency is fine — a document landing a few seconds late in GET_ALL_FILES is rarely a correctness problem.
