Design

An n-ary tree with insertion-ordered children and a per-node active flag. Soft delete = flip the flag; never remove the node, so its subtree stays reachable.

children = defaultdict(list)            # parentId -> child ids, insertion order
active   = defaultdict(lambda: True)

def addChild(p, c):  children[p].append(c)      # append => oldest..newest. O(1)
def markInactive(e): active[e] = False           # tombstone, keep in tree. O(1)

def getActiveOrder():
    out = []
    def dfs(e):
        if active[e]:                            # gate EMISSION on active...
            out.append(e)
        for c in children[e]:                    # ...but ALWAYS recurse children
            dfs(c)
    dfs(ROOT)
    return out                                   # pre-order, oldest..newest

The whole trick: the active check guards whether you output the node, not whether you recurse. An inactive parent is skipped from the list but its active descendants still appear (in hierarchy order). addChild/markInactive O(1); getActiveOrder O(n).

Children are kept in a list and appended, so insertion order = visit order for free. (If entities can also be re-activated, markActive just flips the flag back — no structural change.)

Follow-up trio

  • Multi-threaded — disjoint subtrees are independent: parallel DFS over the root's children, concatenating per-subtree ordered lists. markInactive vs getActiveOrder need a read/write lock (or a snapshot of the active flags) so a traversal sees a consistent view.
  • Streaming — addChild/markInactive arrive online; the structure is already incremental. For frequent getActiveOrder calls, cache the order and invalidate only the affected subtree on change.
  • O(1)-space — traversal is O(height) recursion (iterative explicit stack to avoid it); the output is inherently O(active count). The tree itself is O(n).
