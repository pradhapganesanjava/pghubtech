Part 1 — global shortest gap (single scan)

Walk left→right once, remembering the index of the most recent person and most recent cake. Each time you see one, the candidate gap to the last-seen opposite type on its left is |i - last| - 1; track the minimum. Comparing every adjacent person↔cake pair in one pass captures the global minimum.

def closest_gap(a):
    last_person = last_cake = -1     # last seen indices (-1 = none yet)
    best = INF
    for i, v in enumerate(a):
        if v == 1:                   # person
            last_person = i
            if last_cake >= 0: best = min(best, i - last_cake - 1)
        elif v == 2:                 # cake
            last_cake = i
            if last_person >= 0: best = min(best, i - last_person - 1)
    return best if best < INF else -1

O(n) time, O(1) space. The - 1 converts index distance into the "empty spots between" gap (adjacent → 0).

Follow-up — which cake does person p eat

From person p, scan left and right for the nearest cake (a 2); return the closer index (ties not required). This is exactly #10060 Nearest Cake on a Line.

def nearest_cake(a, p):
    L = R = -1
    for i in range(p, -1, -1):
        if a[i] == 2: L = i; break
    for j in range(p, len(a)):
        if a[j] == 2: R = j; break
    if L < 0 and R < 0: return -1
    if L < 0: return R
    if R < 0: return L
    return L if (p - L) <= (R - p) else R

For many person queries, a two-pass (nearest-cake-to-left, nearest-cake-to-right) answers all in O(n) total — the #821 pattern.

  • Multi-threaded — Part 1 is a reduction (per-segment min gap, merged at boundaries); the two directional passes of the follow-up are independent.
  • Streaming — values arrive online: keep last-person / last-cake indices and update the running min gap in O(1) per element.
  • O(1)-space — Part 1 already O(1); the all-persons follow-up needs O(n) for the two nearest-cake arrays.
