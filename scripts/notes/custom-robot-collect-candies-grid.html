Approach — state-augmented BFS (position + collected bitmask)

With several candies to gather, the order matters, so the search state is not just the cell but (row, col, collected-mask) — a bit per candy. BFS over that state graph gives the fewest moves (every step costs 1).

idx = {candy_cell: i for i, candy_cell in enumerate(candies)}   # bit index
FULL = (1 << len(candies)) - 1
start = (r0, c0, 0)
seen = {start}
q = deque([(r0, c0, 0, 0)])            # row, col, mask, dist
while q:
    r, c, mask, d = q.popleft()
    if (r, c) in idx:
        mask |= (1 << idx[(r, c)])
    if mask == FULL:
        return d
    for nr, nc in neighbors(r, c):
        if in_bounds and grid[nr][nc] != '#':
            ns = (nr, nc, mask)
            if ns not in seen:
                seen.add(ns); q.append((nr, nc, mask, d + 1))
return -1

State space O(rows · cols · 2ᶜ) for c candies — fine for small c (≤ ~12–16).

Alternative when candies are few but the grid is huge

BFS pairwise distances between {start} ∪ candies (c+1 BFS runs), then a TSP bitmask-DP over those c+1 nodes: dp[mask][i] = min cost to have collected mask ending at candy i. O(2ᶜ · c²) — independent of grid size.

Follow-up trio

  • Multi-threaded — level-synchronous BFS: expand all frontier states of a distance layer in parallel, dedup into the next layer. The shared seen set needs a concurrent set / sharded locks.
  • Streaming — candies appear/disappear over time: keep the (cell,mask) BFS layers and, on a change, only re-expand states whose reachable target-mask changed — avoid a full restart.
  • O(1)-space — the visited set is inherently O(rows·cols·2ᶜ). For few candies, the TSP-bitmask route above shrinks state to O(2ᶜ·c) — the practical "small extra state" variant.
