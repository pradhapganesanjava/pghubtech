Approach — weighted interval scheduling with a K cap

Weights mean greedy-by-count fails (a single high-credit course can beat two cheap non-overlapping ones), so DP. Sort courses by end time; for each course binary-search its latest non-overlapping predecessor.

order = sorted(range(n), key=lambda i: end[i])
ends  = [end[i] for i in order]
# dp[i][k] = max credits using order[:i], choosing at most k courses
dp = [[0] * (K + 1) for _ in range(n + 1)]
for i in range(1, n + 1):
    s, e, cr = start[order[i-1]], end[order[i-1]], credit[order[i-1]]
    p = bisect_right(ends, s, 0, i - 1) - 1   # last course ending <= start; -1 -> 0 base
    p = p + 1                                  # map to dp row (1-indexed, 0 = none)
    for k in range(1, K + 1):
        dp[i][k] = max(dp[i-1][k], cr + dp[p][k-1])
return dp[n][K]

O(n log n + n·K) time, O(n·K) space (rollable). Use start[i] < end[j] overlap rules consistently (inclusive vs exclusive endpoints) per the problem statement.

Follow-up trio

  • Multi-threaded — the per-course binary searches for predecessors are independent (precompute p(i) in parallel). The DP itself is sequential in i, but each row's K columns are independent and can be vectorized/threaded.
  • Streaming — courses arrive sorted by end time online: keep the dp rows and, on each new course, binary-search its predecessor and extend the dp by one row in O(K log n) — no recompute.
  • O(1)-space (reduced) — the predecessor jump needs the full dp table, but you can keep only the K-column rows you still reference; without the K cap (1235) it collapses to a single O(n) dp array.
