Approach — rolling hash + binary search on length

"Longest" + a feasibility test that's monotone in length ⇒ binary-search the length L. For a fixed L, ask "does some length-L substring repeat?" using a rolling hash (Rabin-Karp): hash every length-L window in O(1) per slide and drop them into a set; a hash collision (verified) means a duplicate of length L exists.

def longestDupSubstring(s):
    n = len(s); B, MOD = 131, (1 << 61) - 1
    def has_dup(L):
        if L == 0: return 0
        seen = {}
        h = 0; BL = pow(B, L, MOD)
        for i, ch in enumerate(s):
            h = (h * B + ord(ch)) % MOD
            if i >= L: h = (h - ord(s[i-L]) * BL) % MOD
            if i >= L - 1:
                if h in seen and s[seen[h]:seen[h]+L] == s[i-L+1:i+1]:
                    return i - L + 1          # start index of a repeat
                seen.setdefault(h, i - L + 1)
        return -1
    lo, hi, ans = 1, n - 1, ""
    while lo <= hi:
        L = (lo + hi) // 2
        idx = has_dup(L)
        if idx != -1: ans = s[idx:idx+L]; lo = L + 1   # try longer
        else: hi = L - 1
    return ans

O(n log n) average (n per length × log n lengths). Verify on hash hit to dodge collisions; double-hashing makes false positives negligible.

Follow-up trio

  • Multi-threaded — the per-length feasibility checks are independent; probe several candidate lengths in parallel (or shard the window scan for one L across threads, merging seen-sets).
  • Streaming — characters arrive online: maintain rolling hashes for the lengths of interest and a seen-map; report a duplicate the moment a window hash repeats (KMP/automaton if matching against a fixed pattern instead).
  • O(1)-space (per check) — the seen-set is O(n); the alternative deterministic route is a suffix automaton / suffix array + LCP giving O(n) without hashing, at the cost of more machinery.
