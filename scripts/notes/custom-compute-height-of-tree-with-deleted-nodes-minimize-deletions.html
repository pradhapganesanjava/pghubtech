Solution

Part 1 — height skipping deleted nodes

Post-order DFS. A deleted node contributes 0 but still passes its children's heights upward (you "pass through" it). The height is the max number of non-deleted nodes on a root→node path.

def height(u):                 # longest skip-deleted path under u
    best = 0
    for c in children[u]:
        best = max(best, height(c))
    return best + (0 if deleted[u] else 1)

return height(root)            # 0 if no non-deleted node is reachable

O(n) time, O(h) recursion.

Part 2 — fewest extra deletions so height ≤ K

Greedy bottom-up (the greedy-bounded-prune pattern): carry each subtree's kept-height up; the moment a node would push a kept path above K, delete that node (cut), count it, and send 0 upward. Cutting as high as still-valid removes the most depth per deletion.

cuts = 0
def dfs(u):                    # kept-height of subtree at u, after cuts
    nonlocal cuts
    h = 0
    for c in children[u]:
        h = max(h, dfs(c))
    h += 0 if deleted[u] else 1
    if h > K:                  # would exceed the bound -> delete u
        cuts += 1
        return 0               # u (and its level) no longer counts upward
    return h
dfs(root)
return cuts

O(n). (Already-deleted nodes are free; we only spend deletions to honor the bound.)

Follow-up trio — drill on every high-frequency problem

Template: have a multi-threaded, a streaming, and an O(1)-space version ready for any hot problem. For this one:

  • Multi-threaded — subtree results are independent, so fan the children out: concurrent.futures.ThreadPoolExecutor (or a fork-join pool / Java ExecutorService) computes each child's height in parallel; combine at the parent. The only shared state is the cut counter — make it atomic (threading.Lock / Java ReentrantLock or AtomicInteger), or have each call return its cut count and sum. (CPU-bound + GIL → use processes in Python; real parallelism in Java.)
  • Streaming — edges (or deletion toggles) arrive online. Keep each node's current best-child-height; on a new edge or a deleted flip, propagate the height delta up the ancestor chain (a small state-machine update) and keep a running global max — no full re-DFS per event.
  • O(1)-space — recursion is O(h) stack (and n = 2e5 risks a recursion-limit blowup). With a parent array, process nodes in leaves-first / reverse-topological order and fold each child's height into a single height[] array — O(n) time, O(1) extra beyond the output. Equivalent: iterative explicit-stack DFS.
