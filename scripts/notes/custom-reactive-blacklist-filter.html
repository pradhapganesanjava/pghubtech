Design — two sets + emit on visibility flip

Keep a seen set (values that have arrived) and a blocked set (the blacklist). A value is visible iff it has been seen and is not blocked. The whole trick is to emit only when an already-seen value actually flips visibility — never for unseen values or no-op updates.

class Filter:
    def __init__(self):
        self.seen = set()
        self.blocked = set()

    def _visible(self, v):
        return v in self.seen and v not in self.blocked

    def processInput(self, v):
        was = self._visible(v)
        self.seen.add(v)
        if self._visible(v) and not was:
            emit(True, v)                 # newly visible

    def processFilter(self, show, v):     # show=True => make visible (unblock)
        was = self._visible(v)
        if show: self.blocked.discard(v)
        else:    self.blocked.add(v)
        now = self._visible(v)
        if now != was:                    # only a REAL transition emits
            emit(now, v)

All operations are O(1) (hash-set membership). The basic (no-flag) version is the same minus the show argument: processInput emits if not blocked; processFilter emits a seen value's transition.

Why guard on was != now: blocking an already-blocked value, or unblocking a value that was never seen, changes nothing observable — emitting there would be a spurious event.

Follow-up trio

  • Multi-threaded — concurrent processInput / processFilter: guard seen + blocked with a lock (or concurrent sets) and make the read-modify-emit atomic per value, so two threads can't both emit the same flip. Shard by value hash to reduce contention.
  • Streaming — this IS the streaming model: O(1) per event, state is just the two sets; emits happen inline as transitions occur.
  • O(1)-space (per op) — each op is O(1); total state is O(distinct values) (unavoidable — you must remember what's been seen and what's blocked).
