Key insight — it reduces to the tree's height

Because you must keep the root and stay connected, any kept node drags its entire root-to-node path along with it. To maximize the deepest kept node, just keep one deepest root→leaf chain and delete everything else — that's still a valid rooted tree. Deletions can only remove nodes, never lengthen a path, so:

answer = the tree's height (max edges from root to any leaf). The "delete any number of nodes" clause is a red herring for this objective.

Solution

One DFS (or BFS) from the root; return the maximum edge-distance.

def max_depth(u, parent):
    best = 0
    for w in adj[u]:
        if w != parent:
            best = max(best, 1 + max_depth(w, u))
    return best
return max_depth(1, 0)        # O(n) time, O(h) stack

O(n). For n = 2·10^5 prefer iterative DFS / BFS levels to avoid recursion-limit blowups.

Follow-up trio

  • Multi-threaded — subtree depths are independent: parallel DFS over the root's children (fork-join / concurrent.futures), max-combine the results. No shared mutation.
  • Streaming — edges arrive online (each adds a leaf to an existing node): keep depth[node]; a new edge u→v sets depth[v] = depth[u] + 1 and updates a running global max in O(1) — no re-traversal.
  • O(1)-space — BFS by levels and count levels: O(1) extra beyond the frontier queue (and no recursion). Height = (#levels − 1).

Contrast with the deletion problems where deletions DO matter

  • This — maximize depth ⇒ deletions irrelevant ⇒ just the height.
  • #10006 — minimize deletions to bound height ≤ K (deletions are the crux; greedy bottom-up prune).
